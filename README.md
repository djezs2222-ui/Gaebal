# 태블릿 플레이어 0.1.1

**0.1.1: Android 파일 선택기로 연 영상의 입력 처리를 수정했습니다. 문서 주소·한글 파일명·오프셋·권한 오류 회귀 검증과 기존 재생·핀치·팬 검증을 통과했습니다.**

[APK 바로 다운로드 — 약 61MB](https://github.com/djezs2222-ui/Gaebal/releases/download/player-test-0.1.1-7/TabletPlayer-0.1.1-arm64.apk) · [검증 결과](VERIFICATION.md)

개인 실사용을 위한 Kotlin + LibVLC Android 앱의 첫 테스트 버전입니다. 태블릿용 설치 파일은 `TabletPlayer-0.1.1-arm64.apk`입니다. Android 8 이상 ARM64 기기를 대상으로 합니다. 실제 태블릿·NAS·SD·USB 검증은 아직 완료되지 않았습니다.

## 태블릿에서 설치

1. APK를 태블릿에 다운로드하고 다운로드 목록에서 엽니다.
2. Android가 요청하면 해당 브라우저/파일 앱의 ‘출처를 알 수 없는 앱 설치’를 허용합니다.
3. 앱에서 ‘동영상 파일 열기’를 눌러 먼저 영상 재생을 확인합니다.
4. ‘내부 저장소 / SD / USB 연결’에서 이름을 지정하고 사용할 영상 폴더에 접근을 허용합니다. 이후 앱 안에서 폴더를 클릭해 탐색할 수 있습니다.

PC나 터미널 명령은 필요하지 않습니다. GitHub Releases의 테스트 버전 APK 또는 이 대화에 첨부된 APK를 사용합니다. 최신 검증 상태는 VERIFICATION.md를 확인하십시오.

## 구현한 기능

- VLC 기반 로컬 영상 재생, TextureView를 사용하는 1~5배 핀치 확대와 확대 후 드래그 팬, 화면 초기화
- 탐색 막대, 0.5/0.75/1/1.25/1.5/2배속, 내장 자막 선택/끄기, 외부 자막 파일 선택, 파일별 이어보기
- 저장되는 재생목록(최대 100개), 순차 재생, 이전/다음, 순서 변경·목록에서 제거
- Android 폴더 접근 권한(SAF)으로 내부 저장소·SD·USB 연결 및 하위 폴더 탐색
- SMB2 이상 NAS 로그인, 공유 내 폴더 탐색, 로컬 HTTP Range 중계를 이용하는 NAS 재생·탐색
- 파일 이름/크기/날짜 정렬, 개별 선택/전체 선택, 복사·이동·영구 삭제
- 고급 검색: 기본 하위 폴더 포함, 동영상 확장자만, 500,000,000바이트 이상, 최대 제한 없음, 날짜 조건 없음. 최소/최대 MB와 시작/종료 날짜를 수정할 수 있습니다. MB는 1,000,000바이트입니다.
- 검색 결과는 미리보기만 표시합니다. 개별 선택/해제 후 복사·이동·삭제를 별도로 선택해야 합니다.
- 복사/이동 목적지는 중복 없이 최신순 최근 3개를 표시합니다. ‘직접 선택’ → 연결된 내부/SD/USB/NAS → 폴더 탐색 → 새 폴더 → ‘이 폴더 선택’ → 최종 검증 → 실행 순서입니다.

## 파일 보호 방식

실행 전 원본 크기·수정일, 목적지 쓰기 권한, 같은 이름, 전체 필요 용량과 16MB 여유 공간을 확인합니다. 선택 파일끼리 이름이 같은 경우에도 차단합니다. 덮어쓰기는 제공하지 않습니다.

고유한 `.partial` 파일로 복사한 후 SHA-256으로 읽어 검증하고 최종 이름으로 바꾼 뒤 다시 검증합니다. 이동은 원본을 다시 읽어 일치함을 확인한 다음에만 원본을 삭제합니다. 변경·취소·오류가 발생하면 일괄 작업을 중단하고 원본을 보존합니다. 원본 삭제 실패 시 검증된 복사본과 원본이 모두 남습니다. 최종 삭제와 동시 외부 수정 사이를 완전히 원자적으로 잠그는 기능은 없습니다.

삭제는 별도 최종 확인이 있는 **영구 삭제**이며 휴지통/되돌리기는 없습니다. 폴더 일괄 삭제는 제공하지 않습니다. 검색으로 하위 폴더의 영상만 모아 처리할 수 있습니다. 작업 로그는 앱 내부에 저장되며 텍스트로 내보낼 수 있습니다.

앱 강제 종료나 전원 차단 시 자동 재개하지 않습니다. 복사 도중 중단된 `.tabletplayer-….partial` 파일이 남을 수 있습니다. 앱을 다시 열어 로그와 파일을 확인해야 합니다. 복사·이동 중에는 앱을 전면에 두십시오. 시스템 백그라운드 작업/알림 서비스는 아직 구현하지 않았습니다.

## 저장소와 NAS의 현재 제한

- Android 정책상 내부 저장소 전체 루트, Download 루트, Android/data 등의 폴더를 선택할 수 없을 수 있습니다. Movies 등 접근을 허용할 수 있는 하위 폴더를 연결합니다.
- SD·USB는 Android가 인식하고 시스템 폴더 선택기에 표시하는 장치만 지원합니다. 처음 연결할 때 각 저장소의 접근 권한을 허용해야 합니다.
- 남은 용량을 확인할 수 없는 문서 제공자는 안전을 위해 복사·이동을 차단합니다. 일반 로컬 외장 저장소와 SMB를 우선 대상으로 합니다.
- NAS는 서버 주소와 공유 이름을 직접 입력해야 합니다. 네트워크 자동 발견/공유 목록 검색은 미구현입니다. 같은 네트워크에서 먼저 확인하십시오.
- NAS 암호는 메모리에만 두며 앱 프로세스 종료 후 다시 로그인해야 합니다. 저장된 재생목록/최근 NAS 목적지는 재로그인 후 사용할 수 있습니다.
- SMB 프로토콜 최소 SMB2를 강제합니다. NAS별 인증·서명·암호화 호환성은 실서버에서 검증하지 않았습니다.
- 외부 자막은 개인 캐시에 복사해 VLC에 전달합니다. SRT 외 다른 형식과 문자 인코딩별 표시, 자막 동기 조절은 실검증하지 않았습니다.
- 첫 UI는 기능 중심의 기본 화면입니다. 대용량 목록 가상화, 검색 결과 페이지 나누기, 썸네일, 오디오 트랙 선택, 백그라운드 재생은 미구현입니다.
- 서명된 디버그 APK이며 Play Store용 출시 버전은 아닙니다. DRM 재생은 대상이 아닙니다.

## 빌드

- AGP 9.3.1, Gradle 9.5.0, Java 17
- compileSdk 37 (`platforms;android-37.0`), targetSdk 35, minSdk 26
- LibVLC 3.7.7, jcifs-ng 2.1.10
- `./gradlew testDebugUnitTest lintDebug assembleDebug`
- ARM64 APK: `app/build/outputs/apk/debug/app-arm64-v8a-debug.apk`
- 에뮬레이터 APK: `app/build/outputs/apk/debug/app-x86_64-debug.apk`

Windows Java에서 `Unable to establish loopback connection`이 발생하면 짧고 실제 존재하는 임시 경로를 `java.io.tmpdir`와 `jdk.net.unixdomain.tmpdir`에 지정합니다. 이 환경에서는 Windows의 축약 임시 경로 대신 일반 경로를 지정해 해결했습니다. 사용자 태블릿 설치에는 해당하지 않습니다.

## GitHub Actions

지정 저장소: https://github.com/djezs2222-ui/Gaebal

`.github/workflows/android.yml`은 main/codex 브랜치 푸시, PR, 수동 실행 시 테스트·정적 검사·APK 빌드 후 다운로드용 Artifact를 보관합니다. Android 35 에뮬레이터에서 자체 생성 영상의 재생·핀치·팬·배속·탐색·이어보기와 HTTP Range 중계를 검사합니다. codex 브랜치 또는 player-v 태그 푸시에서는 모든 검증이 통과한 뒤 player-test 접두사의 사전 릴리스를 게시합니다. 기존 v1.0.* 태그를 변경하지 않습니다.

현재 GitHub 계정 연결은 확인됐습니다. 실제 원격 빌드·재생 검증·게시 결과는 VERIFICATION.md와 Actions 실행 결과를 확인하십시오.

업데이트 설치 시 같은 서명키가 필요합니다. 현재 APK와 동일한 테스트 키를 비공개 Actions secret `DEBUG_KEYSTORE_BASE64`로 설정해야 로컬 APK와 CI APK를 연속 업데이트할 수 있습니다. 키는 저장소에 커밋하지 않습니다. 이 secret 없이 CI를 실행하면 임시 테스트 키로 빌드되며 다른 빌드와 서명이 달라질 수 있습니다. 기존 앱 삭제로 우회하면 이어보기·재생목록·로그가 지워지므로 먼저 서명을 맞추는 방식을 권장합니다.

## 코드 구성

- `PlayerActivity.kt`: 영상·확대/팬·자막·배속·이어보기
- `Storage.kt`: SAF/SMB 공통 저장소 인터페이스
- `SmbStreamServer.kt`: 토큰이 있는 loopback 전용 HTTP Range 중계
- `FileTasks.kt`: 검색·최종 확인·검증된 복사/이동
- `MainActivity.kt`: 탐색·검색 미리보기·목적지 선택·재생목록·로그
- `FileTasksTest.kt`: 경계값과 원본 보호 단위 테스트
- `SmokeRunner.kt`: 자체 AVC 영상 생성 및 에뮬레이터 재생/제스처 테스트

자세한 실제 실행 결과는 함께 제공하는 검증 결과 문서를 확인하십시오.
